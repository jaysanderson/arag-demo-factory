**Building Solutions with\
Progress Agentic RAG**

*The complete practitioner's guide — grounded in a live, tested
Knowledge Box*

Progress Agentic RAG is a Retrieval-Augmented Generation platform
delivered as a service. It ingests your unstructured data in any format
and any language, indexes it for both keyword and semantic retrieval,
and lets you ask questions in natural language and receive trusted,
cited answers generated by a large language model of your choice. This
book is a hands-on guide to building real solutions on that platform —
from the first API call to a production deployment.

**About this book**

Most API documentation tells you what an endpoint *is*. This book shows
you what an endpoint *does* — because every request and response you
will read here was executed against a live Progress Agentic RAG
Knowledge Box while the book was being written. When you see a JSON
response, an answer, a citation, or an error message, it is a real one
captured from the platform, not an idealized illustration.

The book is organized as a **guide with a full reference appendix**.
Parts 1 through 6 are a narrative you can read front to back: they build
a mental model, then walk through ingestion, retrieval, generative
answers, the knowledge graph, the Retrieval Agent, the SDKs, and
production concerns. Part 7 is an endpoint-by-endpoint reference
generated from the platform's official OpenAPI specifications, so you
can look up any parameter without leaving the book.

**Who this book is for**

- **Application developers** integrating search and generative answers
  into a product, using the REST API or one of the official SDKs
  (Python, JavaScript/TypeScript, .NET).

- **Solution engineers and architects** designing a RAG pipeline:
  choosing models, shaping the data model, tuning retrieval, and
  enforcing security and multi-tenancy.

- **Technical teams evaluating the platform** who want to understand
  exactly what it can do before committing, with concrete, reproducible
  examples.

You do not need prior RAG experience. You do need to be comfortable
reading HTTP requests and a little Python or JavaScript. Chapter 2
defines every term the platform uses.

**How everything in this book was tested**

A dedicated, throwaway Knowledge Box was created in the
aws-ap-southeast-2-1 (Australia, AWS) zone and loaded with a small
synthetic corpus about home energy — solar panels, battery storage, and
electric-vehicle charging. Every capability in the book was exercised
against that Knowledge Box: resources were created and read back, files
were uploaded, searches were run, generative answers were produced and
streamed, and the knowledge graph was queried. The exact responses
appear throughout.

Endpoint signatures, parameter names, types, defaults, and enumerations
are taken directly from the four official OpenAPI specifications that
Progress publishes for the platform:

| **Specification** | **Covers** | **Base URL pattern** |
|----|----|----|
| global (v1) | Accounts, users, zones | https://rag.progress.cloud/api/v1 |
| nucliadb (v1) | Knowledge Box content, search, RAG | https://\<zone\>.dp.progress.cloud/api/v1 |
| nua (v1) | Processing, Predict, agents | https://\<zone\>.dp.progress.cloud/api/v1 |
| zone (v1) | KB management within a zone | https://\<zone\>.dp.progress.cloud |

**Conventions used throughout**

**Code samples** appear in three flavors wherever it makes sense: a raw
cURL call that maps directly to the HTTP request, the **Python SDK**
(nuclia), and the **JavaScript/TypeScript SDK** (@nuclia/core). Reading
the cURL first is the fastest way to understand what any SDK method does
under the hood.

**Placeholders** are written in uppercase: ZONE is your zone slug (for
example aws-ap-southeast-2-1), KB is a Knowledge Box id, ACCOUNT is an
account id, and KEY is whichever token authorizes the call. The chapter
on authentication explains which key each call needs.

**A note on names**

The platform is built on the open-source **NucliaDB** engine and the
**Nuclia Understanding API** (**NUA**). Progress Agentic RAG is the
commercial, managed offering. You will see the names *Nuclia* and
*NucliaDB* in URLs, headers (X-NUCLIA-NUAKEY), SDK package names, and
the OpenAPI specifications — they refer to the same platform this book
describes.
